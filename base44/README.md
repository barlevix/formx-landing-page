# FormX for Base44

The landing page ported to React + Vite + Tailwind — the shape a Base44 app
expects — so it can go in through Base44's GitHub sync rather than being
regenerated by its AI from a URL.

**It renders pixel-identically to the live site.** Verified by screenshotting
both full pages in headless Chrome at 1440×900 and 375×812 and diffing:
0 differing pixels out of 25.9M and 5.8M respectively, with matching page
heights. That is the whole point of this folder — a URL import would recreate
the design and lose the Figma fidelity.

## Try it

```bash
npm install
./sync-assets.sh     # copies media + content.json from ../docs
npm run dev
```

## How it maps onto a Base44 app

| here | Base44 |
| --- | --- |
| `src/pages/Home.jsx` | `src/pages/Home.jsx` — the `/` route |
| `src/formx.css` | import it from the page component, as here |
| `src/useFormX.js` | `src/hooks/useFormX.js` if you prefer their layout |
| `public/assets/*` | `public/assets/*` |
| `public/content.json` | `public/content.json`, or a Base44 entity — see below |
| `index.html`, `vite.config.js`, `tailwind.config.js` | already exist in the Base44 app — do not overwrite |

Only the first five rows move across. The scaffold here exists so the port can
be run and verified on its own.

## The two things that protect fidelity

**`styles.css` ships unchanged.** Every rule, breakpoint and container query is
the same file the standalone site uses. Nothing is re-expressed as Tailwind
utilities — that is what would introduce drift.

**Resets use `:where()`.** The stylesheet used to own `<body>`; here it is
scoped to a `.formx` wrapper. Writing that as `.formx button { font: inherit }`
raises the reset's specificity above component rules like `.cta`, which silently
broke the buttons — the pixel diff caught it at 17.6% drift. `:where(.formx)`
contributes zero specificity, so the cascade behaves exactly as before. Keep it
that way.

## Watch for, once it is inside Base44

- **Host layout.** A Base44 page shell may wrap the route in padding or a
  max-width. `.formx` sets `width: 100%`, but if the page looks inset, the
  wrapper needs to break out of that container.
- **Their global CSS.** This scaffold includes Tailwind preflight, which the
  port already survives. Base44 may ship additional globals; re-run the diff
  after the first sync.
- **Fonts.** Satoshi (Fontshare) and Plus Jakarta Sans + Noto Serif (Google) are
  loaded in `index.html`. Base44 has its own `index.html`, so those three
  `<link>` tags have to be added there or the type will fall back and the
  layout will shift.

## Content

`public/content.json` still drives the backgrounds, reviews and projects, so
Pages CMS keeps working if you keep the GitHub Pages copy. If content should
live in Base44 instead, turn `reviews` and `projects` into Base44 entities and
swap the `fetch('/content.json')` in `useFormX.js` for their SDK — the shape of
the data does not need to change.
